# Model Card: FashionCNN — классификатор изображений одежды

Описание подготовлено по шаблону Google Model Card ([Mitchell et al., 2019, «Model Cards for Model Reporting»](https://arxiv.org/abs/1810.03993)).

| Параметр | Значение |
|---|---|
| Название | `FashionCNN` |
| Версия | 0.1.0 (пакет `fashion-mnist-production`) |
| Тип модели | Свёрточная нейронная сеть (CNN) для многоклассовой классификации изображений |
| Фреймворк | PyTorch 2.2, torchvision 0.17 |
| Исходный код | [`src/fashion_mnist/model.py`](src/fashion_mnist/model.py), обучение в [`train.py`](src/fashion_mnist/train.py), оценка в [`evaluate.py`](src/fashion_mnist/evaluate.py) |
| Происхождение | Рефакторинг [Colab-ноутбука](https://colab.research.google.com/drive/1m-WKcpdE7qCQRipzM4ICgtDRQEpK0xPM) в production-пакет |
| Артефакт | Веса модели (`state_dict`) в `artifacts/fashion_cnn.pt` |
| Число параметров | 42 058 (≈ 170 КБ в float32) |
| Лицензия данных | Fashion-MNIST — MIT License (Zalando Research) |

### Архитектура

```
Вход 1×28×28
 └─ Блок 1: Conv2d(1→32, 3×3, padding=1) → BatchNorm2d → ReLU → MaxPool(2)   → 32×14×14
 └─ Блок 2: Conv2d(32→64, 3×3)            → BatchNorm2d → ReLU → MaxPool(2)   → 64×6×6
 └─ Flatten (2304) → Dropout(p=0.25) → Linear(2304→10)
Выход: 10 логитов (по одному на класс)
```

### Параметры обучения

| Гиперпараметр | Значение |
|---|---|
| Функция потерь | `CrossEntropyLoss` |
| Оптимизатор | Adam, `lr = 1e-3` |
| Размер батча | 64 |
| Число эпох | 5 |
| Dropout | 0.25 |
| Seed | 42 (`seed_everything`) |
| Выбор чекпоинта | Сохраняется эпоха с лучшей accuracy на тестовой выборке |
| Устройство | CUDA / Apple MPS / CPU, выбирается автоматически |

Все гиперпараметры собраны в `TrainConfig` ([`config.py`](src/fashion_mnist/config.py)). Число эпох, размер батча и learning rate можно переопределить через CLI: `poetry run train --epochs 5 --batch-size 64 --lr 0.001`.

## 2. Назначение модели (Intended Use)

### Основное назначение

Модель решает задачу **автоматической категоризации товаров одежды и обуви по изображению**: по фотографии предмета она определяет, к какой из 10 товарных категорий он относится.

Целевой сценарий: модуль автоматической разметки карточек товаров в каталоге интернет-магазина или маркетплейса. Продавец загружает фото, модель предлагает категорию, а при низкой уверенности карточка уходит модератору (подробнее в [Model_BPMN.md](Model_BPMN.md)).

### Предполагаемые пользователи

- ML-инженеры и студенты: эталонный production-пайплайн обучения (пакет, конфиг, CLI, тесты, Poetry, линтеры).
- Команда каталога или контент-модерации: как baseline-классификатор для предразметки товаров.

### Решаемая задача

Многоклассовая классификация (10 взаимоисключающих классов):

| ID | Класс | ID | Класс |
|---|---|---|---|
| 0 | T-shirt/top (футболка/топ) | 5 | Sandal (сандалия) |
| 1 | Trouser (брюки) | 6 | Shirt (рубашка) |
| 2 | Pullover (пуловер) | 7 | Sneaker (кроссовок) |
| 3 | Dress (платье) | 8 | Bag (сумка) |
| 4 | Coat (пальто) | 9 | Ankle boot (ботильон) |

### Нецелевое использование (Out-of-Scope)

- Цветные фотографии «как есть», снимки с фоном, людьми или несколькими предметами в кадре без предварительной обработки.
- Товары вне 10 классов (аксессуары, головные уборы, бельё и т. п.). Модель всё равно вернёт один из 10 классов, потому что у неё нет класса «другое».
- Определение бренда, размера, цвета, материала, подлинности товара.
- Любые решения в отношении людей: распознавание лиц, оценка внешности и т. п.
- Полностью автономная публикация без проверки человеком при низкой уверенности модели.

## 3. Входные и выходные данные

### Вход

| Характеристика | Значение |
|---|---|
| Формат | Тензор `float32` формы `[N, 1, 28, 28]` (N — размер батча) |
| Изображение | Одноканальное (grayscale), 28×28 пикселей, предмет по центру на тёмном фоне |
| Предобработка | `ToTensor()` (пиксели 0..255 → 0..1), затем `Normalize(mean=0.5, std=0.5)` (→ диапазон −1..1) |
| Реализация | `build_transform()` в [`data.py`](src/fashion_mnist/data.py) |

Для реальных фотографий перед моделью нужна та же предобработка, что и для Fashion-MNIST: перевод в оттенки серого, удаление фона, кадрирование по предмету, масштабирование до 28×28, инверсия (светлый предмет на тёмном фоне).

### Выход

| Характеристика | Значение |
|---|---|
| Формат | Тензор логитов `float32` формы `[N, 10]` |
| Предсказанный класс | `argmax(logits, dim=1)` → ID класса 0..9 |
| Уверенность | `softmax(logits)` → вероятности классов; максимальная вероятность используется как confidence score |

## 4. Факторы (Factors)

Факторы, влияющие на качество модели:

- **Визуальная близость классов.** Рубашка, футболка, пуловер и пальто на силуэтах 28×28 почти неразличимы: это главный источник ошибок (см. раздел 8).
- **Условия съёмки.** Модель обучена на стандартизированных изображениях (центрирование, однородный фон, grayscale). Ракурс, фон, освещение, наличие модели-человека и т. п. дают сдвиг распределения (domain shift).
- **Цвет и текстура.** При переводе в grayscale и сжатии до 28×28 теряются цвет, принт и фактура, поэтому модель опирается в основном на силуэт.
- **Аппаратная платформа.** Результаты на CUDA, MPS и CPU могут незначительно различаться из-за недетерминированности операций.

## 5. Метрики (Metrics)

| Метрика | Зачем используется |
|---|---|
| **Accuracy** (основная) | Доля правильно классифицированных изображений. Корректна, так как классы в Fashion-MNIST сбалансированы (по 1000 изображений каждого класса в тесте). Вычисляется в `evaluate()` и логируется на каждой эпохе. |
| **Cross-Entropy Loss** | Функция потерь при обучении, контроль сходимости (логируется средний loss за эпоху). |
| **Precision / Recall / F1 по классам, macro-F1** | Показывают, на каких категориях модель ошибается. Для каталога важно, чтобы ни одна категория не страдала систематически. |
| **Матрица ошибок** | Выявляет пары классов, которые модель путает. |
| **Coverage @ порог уверенности** | Доля товаров, которые модель может разметить автоматически при заданном пороге confidence, и accuracy на этой доле. Определяет нагрузку на модераторов. |

## 6. Данные для оценки (Evaluation Data)

- **Датасет:** тестовая часть Fashion-MNIST (`t10k`), 10 000 изображений, по 1 000 на класс.
- **Почему:** это стандартный отложенный тест-сет, не пересекающийся с обучающей выборкой. На нём сравниваются модели в литературе.
- **Предобработка:** та же, что при обучении (`ToTensor` + `Normalize(0.5, 0.5)`), без аугментаций.

## 7. Данные для обучения (Training Data)

- **Датасет:** [Fashion-MNIST](https://github.com/zalandoresearch/fashion-mnist) (Zalando Research), обучающая часть: 60 000 изображений, по 6 000 на класс.
- **Источник:** фотографии реальных товаров из каталога Zalando, переведённые в grayscale 28×28.
- **Загрузка:** `ensure_fashion_mnist()` скачивает архивы с зеркал (Google Storage → GitHub → S3) и проверяет целостность IDX-файлов (magic number и размер).
- **Аугментации:** не применяются.
- **Валидационная выборка:** отдельно не выделяется (см. ограничения).

### Самые частые ошибки

| Истинный класс → предсказанный | Количество ошибок (из 1000 изображений класса) |
|---|---|
| Shirt → T-shirt/top | 109 |
| T-shirt/top → Shirt | 92 |
| Coat → Shirt | 71 |
| Shirt → Pullover | 65 |
| Coat → Pullover | 65 |

Почти все ошибки приходятся на группу «верхняя одежда с рукавами» (футболка, рубашка, пуловер, пальто). Брюки, сумки, обувь и платья распознаются с F1 выше 0.9.

### Качество в зависимости от порога уверенности

| Порог max softmax | Доля авторазметки (coverage) | Accuracy на этой доле |
|---|---|---|
| нет порога | 100% | 91.15% |
| ≥ 0.5 | 97.1% | 92.55% |
| ≥ 0.7 | 88.0% | 95.92% |
| ≥ 0.9 | 73.7% | 98.55% |

Эта таблица используется для выбора порога в бизнес-процессе: например, при пороге 0.9 модель автоматически размечает около 74% товаров с точностью около 98.5%, а оставшиеся 26% уходят на ручную проверку.

## 9. Этические аспекты (Ethical Considerations)

- **Персональные данные:** датасет содержит только изображения товаров, без людей и персональных данных.
- **Риски ошибок:** неверная категория ухудшает поиск и может привести к некорректным рекомендациям или штрафам продавцу за «неправильную» карточку. Поэтому решения с низкой уверенностью передаются человеку, а у продавца должна быть возможность оспорить категорию.
- **Неравномерное качество по классам:** категория Shirt распознаётся заметно хуже остальных (F1 0.74), значит продавцы рубашек чаще будут сталкиваться с ошибками. Это нужно учитывать при выборе порога и мониторинге.
- **Культурная и ассортиментная предвзятость:** данные взяты из каталога одного европейского ритейлера, поэтому одежда других регионов и стилей может распознаваться хуже.

## 10. Ограничения и рекомендации (Caveats and Recommendations)

### Ограничения

1. **Нет отдельной валидационной выборки.** Лучший чекпоинт выбирается по accuracy на тестовой выборке, поэтому итоговая оценка может быть немного оптимистичной. Рекомендуется выделить validation split (например, 10% от train) и использовать тест только для финальной оценки.
2. **Domain shift.** Fashion-MNIST сильно упрощён по сравнению с реальными фотографиями товаров. На реальных данных качество будет ниже без дообучения и правильной предобработки.
3. **Закрытый набор классов.** У модели нет класса «неизвестно», поэтому любой вход будет отнесён к одному из 10 классов. Для отсеивания нужен порог уверенности или отдельный OOD-детектор.
4. **Калибровка вероятностей не проводилась.** Значения softmax используются как confidence, но они могут быть переуверенными. При необходимости применить temperature scaling.
5. **Короткое обучение.** 5 эпох без аугментаций и scheduler: это baseline, а не предел качества архитектуры.
6. **Нет инференс-сервиса.** В репозитории есть пайплайн обучения и оценки (`train`, `evaluate`). REST-сервис для онлайн-предсказаний описан в [Model_BPMN.md](Model_BPMN.md) как целевая схема внедрения.

### Рекомендации по применению

- Использовать модель как **ассистента разметки**, а не как единственный источник решения: автоматически применять категорию только при confidence ≥ выбранного порога (рекомендуется 0.9).
- На вход подавать изображения, предобработанные так же, как Fashion-MNIST.
- Перед промышленным использованием дообучить модель на реальных фото каталога и пересчитать метрики по классам.
- Мониторить в продакшене долю ручных проверок, долю исправлений категории модератором и распределение предсказанных классов. Рост этих показателей сигнализирует о дрейфе данных.
- Для улучшения качества на группе Shirt / T-shirt / Pullover / Coat: аугментации, более глубокая сеть, больше эпох, изображения большего разрешения.

## 11. Воспроизведение

